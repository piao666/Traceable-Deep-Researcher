## 1. 设计和执行顺序

1. schema 004 建立 export_jobs。冻结 report_version、format、renderer_version 组合唯一；任务完成在同一事务写报告、report.ready、导出队列和任务终态。
2. 单独 ExportWorker，文件生成在独立线程中运行，不阻塞研究 worker/HTTP 事件循环。导出只读取不可变版本，不调用模型、不重跑研究。每格式独立状态与重试，失败保留正文成功状态。
3. 导出领取、续租和发布使用独立 fencing token；文件使用任务、版本、job 和 attempt 派生命名，先写临时文件后原子替换。过期 worker 不能覆盖当前已发布引用。
4. 下载路由验证任务、格式和作业归属，报告历史版本仍可下载。重试操作幂等；正文读取和研究结果不等待导出。
5. 旧 WS path 兼容等到三种导出终态再发，仅用于旧客户端；新客户端根据 task 终态结束研究加载，并分别展示导出状态。
6. 服务端任务报告为权威版本；旧客户端仅可回写相同正文的显示投影，禁止旧缓存覆盖新正文。前端历史始终从服务端分页读取并合并本地旧记录，不依赖浏览器在报告完成时保存。
7. 执行显式 schema 迁移前，用 SQLite backup API 创建一致性备份（包含 WAL 已提交内容）；未知 schema 和迁移失败保持原库可恢复。检查实际旧 JSON 是否存在，缺少旧文件不伪造迁移结果。
8. 隔离测试覆盖一格式失败而其他成功、重复重试、真实 PDF/DOCX 小文档、无浏览器历史持久化、数据库升级/备份恢复、容器替换、桌面/手机刷新恢复。不调用真实研究模型或搜索服务。
